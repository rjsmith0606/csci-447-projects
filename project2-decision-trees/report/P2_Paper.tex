\section{Problem Statement and Hypothesis}
The goal of this project is to implement and analyze decision trees for classification and regression. A tree grown to completion keeps splitting until its leaves are pure, which allows it to fit noise in the training data. Post-pruning addresses this by removing subtrees that do not help on data not used for training. We implement univariate decision trees using gain ration for classification and mean squared error (MSE) for regression, and compare fully grown trees to trees simplified with reduced error pruning (REP) on six UCI datasets.

We test the following hypotheses using $5 \times 2$ cross validation ...
\begin{enumerate}
    \item \textbf{H1:} Reduced error pruning produces 50\% smaller trees than fully grown trees on every dataset.
    \item \textbf{H2:} Pruned trees achieve lower mean test error than unpruned trees on a majority (at least four) of the six datasets.
\end{enumerate}
H1 is falsified if any dataset shows a smaller reduction, and H2 is falsified if the pruned tree has the lower mean error on three or fewer datasets.

\subsection{Preprocessing}
Decision trees choose splits by comparing a feature against a threshold or by branching on its distinct values, which has several consequences for preprocessing. A rescaling of a numeric feature does not change which splits are possible, so we apply no normalization. Categorical features are split natively with one branch per distinct value, so we do not use one-hot encoding or cyclic encoding. Numeric features receive binary splits and categorical features (nominal or ordinal) receive one branch per value. We store a record of which features are numeric and which are categorical as a map from feature name to type alongside each processed dataset. The dataset-specific steps are as follows.
\begin{itemize}
    \item \textbf{Unique identifiers:} A feature that is different for every instance would isolate each training example in its own branch, which cannot generalize to unseen data. We therefore remove the sample code number from Breast Cancer and the model name from Computer Hardware.
    \item \textbf{Breast Cancer:} The bare nuclei feature has 16 missing values, marked with ``?''. We replace each with the most common value of that feature rather than dropping the rows, so that all 699 instances are kept. The nine features are integer scores from 1 to 10, and we treat them as numeric.
    \item \textbf{Car Evaluation:} All six attributes (buying price, maintenance cost, doors, persons, luggage boot size, and safety) are ordinal. We treat them as categorical and split on every distinct value.
    \item \textbf{Congressional Voting:} In this dataset a ``?'' does not mean the value is unknown; it means the representative did not vote yea or nay. We therefore keep it as a third category for each of the sixteen features.
    \item \textbf{Abalone:} The sex feature (male, female, infant) is categorical, and the remaining seven measurements are numeric.
    \item \textbf{Computer Hardware:} In addition to the model name, we remove the vendor name, which has many distinct values that each cover only a few instances, so a multiway split on it would fragment the data. We also remove the estimated relative performance (ERP) column as it is the dataset authors' own linear regression estimate of the target, so using it as a feature would give the tree another model's prediction of the answer. The six remaining hardware attributes are numeric.
    \item \textbf{Forest Fires:} Month and day are categorical, and we do not apply a cyclic encoding. The spatial coordinates and the weather and fire-index measurements are numeric. The burned area is heavily right-skewed, so we apply the transformation $\ln(x+1)$ to it before training. All reported Forest Fires errors are therefore on the log scale.
\end{itemize}

\subsection{Evaluation Protocol}
To obtain a fair comparison between fully grown and pruned trees, we separate the data into three roles: training, pruning, and testing. First, 20\% of each dataset is drawn at random and held out as the pruning set. This set is never used to train a tree or to report test performance. The remaining 80\% is used for $5 \times 2$ cross validation. In each of five repetitions, we shuffle this 80\% and split it into two equal folds. We then train on the first fold and test on the second, and then reverse the roles, which produces ten train/test pairs per dataset.

For each of the ten train/test pairs, we proceed as follows:
\begin{enumerate}
    \item Grow a tree to completion on the training fold and record its error on the test fold, along with its number of nodes. This is the unpruned result.
    \item Make a copy of the tree and apply reduced error pruning using the pruning set.
    \item Record the pruned tree's error on the same test fold, along with its number of nodes. This is the pruned result.
\end{enumerate}
Because the pruned and unpruned trees are evaluated on identical folds, their results are directly paired. The pruning set is drawn once per run and shared across all repetitions.

For classification we report the classification error, the fraction of test instances predicted incorrectly:
\begin{equation}
    \text{Classification Error} = \frac{1}{N}\sum_{t=1}^{N} \mathbf{1}\left[\hat{y}^t \neq y^t\right],
\end{equation}
and for regression we report the mean squared error,
\begin{equation}
    \text{MSE} = \frac{1}{N}\sum_{t=1}^{N} \left(y^t - \hat{y}^t\right)^2,
\end{equation}
where $N$ is the number of test instances. Tree size is the total number of nodes, internal and leaf. We report the mean quantity over the ten folds. To evaluate H1, we compute the reduction in tree size as $1 - \bar{s}_{\text{pruned}} / \bar{s}_{\text{unpruned}}$, where $\bar{s}$ is the mean node count over the ten folds. To evaluate H2, we compare the mean test error of the pruned and unpruned trees on each dataset and count the datasets on which the pruned trees have the lower mean.

\section{Experimental Results}
We evaluate fully grown and reduced error pruned decision trees using $5 \times 2$ cross validation on each of the six datasets, as described in Section 2.3. We report classification error for the three classification datasets and mean squared error (MSE) for the three regression datasets, along with the number of nodes in each tree. Every value is the mean over the ten test folds, and values after the $\pm$ sign are standard deviations over those folds. Both trees are tested on the same folds, so the pruned and unpruned results are paired.

\subsection{Classification}
Table~\ref{tab:classification-results} reports classification error for the unpruned and pruned trees on the three classification datasets, and Figure~\ref{fig:error} (left) shows the same comparison.

\begin{table}[h]
    \centering
    \begin{tabular}{lccc}
    \hline
    Dataset & Unpruned & Pruned & Folds improved by pruning \\
    \hline
    Breast Cancer   & 0.0505 $\pm$ 0.0128 & 0.0426 $\pm$ 0.0087 & 6/10 \\
    Car Evaluation  & 0.0971 $\pm$ 0.0135 & 0.1247 $\pm$ 0.0137 & 0/10 \\
    House Votes     & 0.0747 $\pm$ 0.0244 & 0.0500 $\pm$ 0.0151 & 4/10 \\
    \hline
    \end{tabular}
    \caption{Classification error ($5 \times 2$ CV mean $\pm$ standard deviation) for the unpruned and pruned trees. The last column gives the number of the ten folds on which the pruned tree had a strictly lower error than the unpruned tree.}
    \label{tab:classification-results}
\end{table}

Pruning lowers the mean error on Breast Cancer and House Votes, by 15.6\% and 33.1\% respectively. On Car Evaluation, pruning raises the error by 28.5\%, and the pruned tree is worse on every one of the ten folds. On Breast Cancer and House Votes the improvement is not uniform across folds. The pruned tree is strictly better on six folds for Breast Cancer, and on only four folds for House Votes, where five of the ten folds are ties and the pruned tree is worse on one.

\section{Main Lessons Learned (UPDATE)}
Through the implementation of this project, we learned the critical importance of feature scaling; without normalization, the Minkowski distance is skewed toward features with larger magnitudes. We also observed that the choice of $k$ and $\gamma$ can lead to significant overfitting or underfitting, reinforcing the need for a robust tuning pipeline like random search. Finally, we learned that "data reduction" is not a one-size-fits-all process. Removing noise (Editing) and removing redundancy (Condensing) serve different purposes and yield different results depending on the dataset.
